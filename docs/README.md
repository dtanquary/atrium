# Wallpaper docs

One file per wallpaper, recording what the code can't: how each scene works, why it's built the way it is, its settings, cost, shortcuts, Dave's feedback, and ideas for next steps. Read the scene's doc before changing it, and update the doc in the same commit as the change. The app, commands and conventions are in `../CLAUDE.md`.

## Screenshots

The README's screenshots live in `docs/images` as 1600-pixel JPEGs of the wallpaper alone. All of them were rendered afresh on 2026-09-29 (except `the-moon-vs-dial-a-moon.jpg`, a check against NASA's frames) by the snapshot test at 2x Retina, which is the same pixels without switching the desktop or touching settings. For example: `SNAPSHOT_DEFAULTS="galaxy.kind=Whirlpool" SNAPSHOT_SCENE=Galaxy swift test -c release -Xswiftc -enable-testing`, with `SNAPSHOT_APPEARANCE=light|dark` for the two looks; the settings for most are in each wallpaper's doc. Random ones were picked from three or four rolls. A few need more than the test gives them:
- **Live data** comes from the app's caches in `~/Library/Caches/com.dtanquary.atrium`, since the test never fetches: seed the Sun's SDO frames and Wind's satellite tiles for today first (their URLs are in `SunImages` and `Imagery`). Earth from Orbit's night side needs a place where it's night: `SNAPSHOT_DEFAULTS="latitude=25,longitude=78"`.
- **Rain on Glass's frost** bakes off the main thread and never lands in the synchronous render test. It needs a throwaway `async` copy of the test that yields with `Task.sleep` between frames (spinning the run loop isn't enough: the test holds the main queue).
- **Moving pictures** (`<slug>.webp`, the first of each wallpaper's in the README) are the website's 12 s preview loops (`site/media.sh previews`, in the looks its `PREVIEWS` list sets) as animated WebP, 640 wide at 15 fps, a third to a quarter the size of a GIF of the same loop: `site/media.sh preview-fish-tank`, then `ffmpeg -i site/public/media/preview-fish-tank.hevc.mp4 -vf fps=15,scale=640:-2:flags=lanczos f/%03d.png && img2webp -loop 0 -lossy -q 70 -m 4 -d 67 f/*.png -o docs/images/fish-tank.webp`. Being loops, they repeat without a jump. (Pixel Window Seat has four more, three of its Earth orbit and one of its train, which aren't on the website: [its doc](pixel-window-seat.md) has their recipes.) Aurora, Deep Space Tour, Flowing Gradient, Galaxy, Lava Lamp, Meander, Nebula, Solar System Tour and Weather broke into blocks as plain WebP, so each of their frames is a keyframe (`-kmin 0 -kmax 1`). Deep Space Tour's zoom over a star field changes every pixel every frame, so it's 10 fps at q50 (`-d 100`), 5 MB, and Schlieren's Warm air, turbulent across the frame, is the same with a keyframe every frame, 2.3 MB; the rest are 16 KB to 3 MB. In a README table each is an `<img width="1600">`, the stills' width: GitHub splits a table's columns by its images' pixel widths, so a plain 640-wide one beside a still gets under a third of the row. The test steps a fixed 30 fps whatever the power settings, so they're always full speed. Below about q70, slow scenes lose frames (WebP merges ones that look the same) and step instead of flowing. WebP redraws only what changed, so smooth scenes (gradients, soft clouds, a slow zoom) break into blocks within seconds: give those a keyframe every frame (`-kmin 0 -kmax 1`), and look at the result 9 s in. A scene that changes every pixel every frame (film grain, a zoom over a star field) comes out many MB, so lower its frame rate or use a still.
- **Settings** screenshots (`settings-*.jpg`) are `SETTINGS_SHOT="<page>" swift test --filter settingsWindow`, saved as JPEG. The test's own defaults domain is `swiftpm-testing-helper`; clear anything a throwaway test left there.

- **Peg Board's** are drawn at the size they are shown at (`PEGBOARD_STILL`, in [its doc](peg-board.md#checking-it)): its sheet is dotted with holes, and a still reduced afterwards shows a weave.

Add or refresh one whenever a wallpaper's look changes. Settings shows one of them behind the top of each wallpaper's page: a 1200-pixel copy in `Sources/Atrium/Resources/preview-<name>.jpg`, plus `preview-<name>-light.jpg` for a Light Mode look. Refresh it with the screenshot: `sips -Z 1200 -s formatOptions 70 docs/images/nebula-hubble.jpg --out Sources/Atrium/Resources/preview-nebula.jpg`.

## Dave's direction so far

- **Favourites:** Nebula first, then Flowing Gradient. They set the bar for the rest.
- **Real over made up:** real data (the real sky, weather and ISS at his location) and colours from real sources (nebula palettes after real objects). He was delighted that Live Sky uses his actual location.
- **Variety without repetition:** a new look on each load (Nebula, Lava Lamp), and slow, seamless cycling when left running, never a hard cut. On 2026-09-26 he asked for Shuffle: Settings → General moves the desktop on to a random wallpaper every 5 minutes to every day, from a checklist of wallpapers, and picking one by hand starts the clock over. It sits beside Open at Login, which the menu already had.
- **Calm motion:** ambient only, with no mouse interaction. Anything flashy or bouncing is distracting (the ISS label was made static). Nudge speeds by small steps.
- **Colours in one family:** jewel tones like Flowing Gradient's. He called Lava Lamp's green-in-blue ugly. Nebulae shouldn't be pink every time.
- **Light and Dark Mode:** scenes that suit both should follow the system appearance (Lava Lamp, Flowing Gradient).
- **Tunable:** options go in the Settings window as data (knobs, switches, palettes), so he can tweak until it looks right. On 2026-09-26 each page got the wallpaper running live behind a glass header, trialled on Nebula first: "yeah the live preview is awesome, add it to all of them."
- **Easy on the battery:** frozen in Low Power Mode, paused when covered. On 2026-09-26 he asked to be able to override this, for demos on battery: Settings → Power has a frame-rate menu (Freeze, 15, 30, 60) for mains power, battery and Low Power Mode, and the menu bar has Full Speed on Battery. Later that day he raised the defaults from 30 and 15 fps to 60 fps plugged in and 30 fps on battery: "it seems to run fine for me on 30 on my battery but we can monitor." Watch battery life and heat at these rates. On 2026-10-11 he asked for a Pause at the top of the menu that turns into Resume: it holds every display on its frame, a wallpaper picked or shuffled to meanwhile fades in and is held too, and it isn't remembered across a relaunch. A timed pause was left out. On 2026-10-13, asked for the best performance plugged in and the best battery life unplugged, he chose a 120 fps choice for displays that offer it, with 60 kept as the plugged-in default, and a cap for each wallpaper on battery for slow ones, whose lower rate can't be seen. Battery savings may trim work that can't be seen, each shown to him side by side first. Measured on 2026-10-14 on battery, the whole Mac's draw (the battery gauge's one-minute averages, so about ±0.4 W) over 6.1 W with Atrium quit: what a wallpaper adds fell from 2.3 to 1.0 W for Nebula, 1.6 to 0.8 for Live Sky, 2.1 to 0.9 for Meander, 1.8 to about nothing for Galaxy, 2.0 to 1.5 for Schlieren, 2.7 to 2.2 for Fish Tank, 0.9 to 0.6 for Pixel City, and by 0.2 W or less for Murmuration, Rain on Glass and Etching, between 0.113.0 and 0.115.0. WindowServer, which puts every frame on screen, fell from about 18% of a core to 5–10% for the capped ones. For the README (2026-10-14), every visible wallpaper was measured once more on battery at standard settings: the whole Mac drew 3.9 W with the calmest (Peg Board, Game of Life, Galaxy, Earth from Orbit) to 6.2 W with the busiest (Wind, Rain on Glass, Lava Lamp, Fish Tank), but the idle Mac was measured only at the start (4.5 W) and its draw fell by at least 0.6 W during the run, so no wallpaper's own share can be told to better than that. Dave chose the safe wording, "dont make claims per wallpaper until we do more in depth testing later": the README says about 2 W for the busiest, under 1 W for the calmest. The fixed script measures the idle Mac before and after every wallpaper; that run is still to do.
- **Settings as a real Mac window** (2026-09-29): after a review against Apple's guidelines it stopped floating above other apps (every page has its own live preview now), joins the Dock and ⌘-Tab while open, and got search, a remembered page, the standard menus and VoiceOver fixes. macOS 26 is the minimum, and the build is stamped with the real SDK so it gets Liquid Glass.
- **Toward 1.0** (2026-09-29): a free DMG from GitHub Releases, signed ad hoc and not notarised (Gatekeeper's Open Anyway, in the README), and no App Store for now; Apple silicon only. Match the lock screen is opt-in and puts the user's wallpaper back. The app icon is "a skylight onto the cosmos" ([app-icon.md](app-icon.md)). Photos and data must be public domain or openly licensed, and credited with source and license links in About; MIT covers the code only (NOTICE).
- **Betas before 1.0** (2026-10-04): the DMG is now signed with Dave's Developer ID and notarised (`release.sh`), so there's no Open Anyway step. The first release is a beta marked Pre-release on GitHub, at whatever version is current when Dave cuts it; 1.0.0 waits until he's run a release build for a while.
- **Unfinished, hidden for 1.0** (2026-09-30): A Tree for the Year and Campfire aren't hitting the mark yet, so they're flagged `unfinished` (see their docs to revisit). Merging Game of Life and Turing Patterns into one wallpaper is on hold while Dave thinks it over; the case against was that they share no engine and few settings.
- **Three new ones** (2026-10-10 to 12): from a brainstorm ([ideas.md](ideas.md)) he picked Black Hole, Meander and a train window for Pixel Window Seat. Each was researched and mocked up for him to choose from, then built in steps behind the `unfinished` switch while he tested them. On 2026-10-12 he asked for their README and site pictures and, asked which to unhide, said all three: they're in the app for everyone from 0.109.0.
- **Etching** (2026-10-12): he asked for a wallpaper after the two-dial drawing toy, "where intricate public domain images become slowly drawn out over time starting from fresh", and for research and mock-ups first. Having seen them he chose the unbroken line with shading over a line that lifts, "Screen alone now, frame later", the line's width "Both, as a setting", a Speed slider "in case a user wants to see it go faster", and ruled "nothing religious" for the pictures (classical myth is fine). He put it ahead of the peg board: "the etch one is looking really really good". It was built that day behind the `unfinished` switch, and he named it Etching, for the old prints it draws ([etching.md](etching.md)).

- **Etching, Peg Board and Ant Colony shown** (2026-10-13): having run all three on his desktop ("ant colony is great, etching is great"; of Peg Board, "pictures are hard to make out, but the pattern looks good ... the color options are good", so its pictures are being drawn afresh and more patterns added), he said "unhide all 3 of the new ones": they're in the app for everyone from 0.111.0. Ant Colony keeps both its gels "for now".
- **The menu as pictures** (2026-10-12): with 28 wallpapers listed, "the dropdown menu bar is getting really long". Offered a short list of recent picks, favourites, mood submenus or a grid of pictures, he chose "a really slick liquid glass modern style Thumbnail grid in the menu", keeping the menu's other rows. From four mock-ups (five across with the name read out on hover; names under each picture; grouped by mood; the same at 40 wallpapers) he picked the first: "A looks great", "your design for A is perfect". The menu still closes on a pick, and the list of names stays as a General setting "for keyboard and voiceover accessibility needs". Measured on the mock-ups with 28 wallpapers, the grid is about 550 points tall where names under each picture came to about 690, grouping by mood to about 635, and the list of names to about 800. Seeing it built, on 2026-10-13, he moved Pause from the top of the menu down beside Shuffle: "the pause button now seems out of place alone up there", and the two belong together since "they control high level functions".
- **Small updates** (2026-10-10): "my goal is to prevent users from having to re download the whole thing over and over as i add more wallpapers." He asked about publishing a delta with each release; after research and tests he chose the design that needs no chain of deltas. An update now fetches only the files that changed, a few MB instead of 400 ([updates.md](updates.md)).
